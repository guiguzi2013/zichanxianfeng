## 技能零：从繁杂信息中找到我们需要的内容（核心能力，2026-09-02 用户强调）

**场景**：原始信息（公告/页面/表格/附件）混杂大量无关内容（免责声明、交易规则、介绍性文字），
我们必须从中准确找出**需要的字段**（本金/利息/抵押物/债务人/担保方式/保证人/司法状态等）并填入。

**抓取核心要求（2026-09-02 用户强调，铁律）**：**不管用哪种方法/哪个程序（httpx 接口、Playwright 渲染、正则、LLM），目的是把原文关键信息抓取到并格式化到我们网站**——遇到任何与抓取/爬虫相关的事都要明白这一点。抓不到就要换方法（接口→渲染→解析），不能因"接口没有"就放弃（例：465 公告 HTML 无表格，但页面"标的物属性"区块 Playwright 能抓到——用页面增强补上并格式化）。

**抓取与回填规则（2026-09-02 用户正式定规）**：
- **抓取**：原文用各种方法（接口/渲染/解析）查看有无表格——**有表抓表**（在我们详情页自建表填入对应信息）；**无表**则查找债权相关关键信息段落，**整段抓取**回填到详情页
- **回填**：详情页表格**首选按原文表格对应的内容填写**（一般原文有表的信息比较全面，基本能满足要求）；**没有表的从描述中找到对应内容填写**
- **信息源四层检查（一个不漏）**：①公告接口 HTML 表格 ②页面 `<table>` 元素（Playwright）③页面属性 div 区块（标的物详情/属性）④附件（资产清单/评估报告/判决书）

**防重复犯错机制（2026-09-02 用户要求，每次抓取必走）**：
1. **回填完整性对照清单**（自建表抓完后逐项核对，表格里每个有值字段必须回填到 detail）：
   - 债务人（**全部**，资产包多户 + 户数；当前名必须是完整户名才保留，否则用首户名）
   - 本金 / 利息 / 罚息 / 其他费用 / 本息合计
   - 担保方式 / **保证人**（表格"保证人：xxx"合并去重）/ 抵押物（类型 + 描述）
   - 司法状态 / 地区 / 拍卖时间 / 状态 / 折扣
2. **错误台账**：用户每次指出的错误/遗漏记入本库"抓取回填错误台账"（见下），每次抓取前**对照台账检查是否同类问题**，同类禁止再犯
3. **信息源检查**：每次抓取先过"四层信息源"，确认都查过才动手，防"只抓一层漏其他"（453 漏 kv、465 漏页面 table、452 漏保证人/债务人，都是只抓了一部分）

**方法论（持续总结，每个修改工作都要沉淀一条）**：

1. **信息源分层识别**：一个页面/文档常有**多个信息源**，先识别全部再逐个提取。
   京东债权页 = ①公告表格（queryProductDescription 的"债权情况说明"表）②**页面属性区块（"标的物详情"表：债权本金/有无抵质押物/担保方式/抵质押物类型/抵质押物地址）** ③附件（资产清单/评估报告/判决书）——只抓公告表格会漏掉"标的物详情"（453 案例：抵押物未披露但标的物详情表里有完整地址和类型）
2. **属性区块可能是表格结构**：innerText 是"键\n值"隔行、无冒号（"标的物详情\n债权本金\n￥10000000\n有无抵质押物\n有…"），不是"键：值"文本行。解析要**兼容两种形态**（冒号行 + 键值隔行，值行不能是已知键）
3. **键名变体**：同一字段不同来源用词不同（"担保方式"vs"抵保方式"、"抵质押物地址"vs"押品地址"、"标的物所在地"）。用**已知键集合匹配**（含变体），不精确匹配单一词
4. **认清金额语义**："贷款发放金额/债权本金(页面)"可能是**原贷额**，不是**当前本金余额**；"本金余额/债权合计"才是当前值。权威值优先级：表格 kv"本金余额" > 横表金额列 > 页面属性(识别为发放金额时慎用) > 接口 claimsMoney(不可靠,最后兜底)
5. **竖排表 3 列行 [组名,键,值]**（["债权基本情况","贷款发放金额","10000000.00 元"]）：别当 [键,值,键2] 错位解析（453 案例：金额张冠李戴）
6. **免责/注释段落是噪声**：提取时过滤"注：/不承担任何/仅供参考/瑕疵/请竞买人/可能已被/查封/详见合同"等——"抵押房地产可能已被查封…不承担法律责任"不是抵押物描述
7. **标题提取防误匹配**：杂质词要覆盖易混淆场景（"**对应**的从权利"的"对"≠"对债务人"，加"对应/从权利/借款合同"到 BAD 词）
8. **完整性自检**：表格/属性区里有的字段必须提取填入，用户核对原文后反馈"与原文不符"= 提取遗漏，必须排查修复并总结方法点
9. **竖排键值表用键值对渲染**（2026-09-02 453 自建表失真）：单列表头+键值行（"债权情况说明"）的竖排表，前端若用 AntD 横表渲染会**只显示键、值全丢**（图2 表头=所有键）——必须检测键值表形态（表头非空列≤1 且存在 键→值 行），用键值对展示（2列行[键,值]、3列行[组名,键,值] 显示组名小标题+键值、长文本段落）
10. **合计行判定只查前2列**（2026-09-02 448 误判）：`_is_summary_row` 查前3列会把"担保情况"描述里的"…房产**合计**25,661.01平方米"（第3列）误判为合计行→金额全错。合计行首列是"合计/总计/小计"，只查 row[:2]
11. **整包合计取合计行最右数字**（2026-09-02 448）：合计行常因合并单元格**列错位**（行数<表头列数，如['合计',本金,利息,费用,总额]5列 vs 表头7列），按列索引取值会错位——取合计行**最后一个数字**（汇总列在最右）
12. **批量修改后必须复查全量**（2026-09-02 自查教训）：修单条(453)≠全量好，批量(89条enrich/补车位/重算金额)后必须跑复查脚本（缺失统计+异常值扫描如"本金>合计"），0 异常才算完成
13. **资产包按户拆分**（2026-09-02 449）：多户资产包表格（序号/债务人/本金/利息/担保情况列）按户拆成独立债权（债务人/本金/抵押物各自独立），PreviewPage 勾选哪户尽调；拆分要点：①列定位按表头关键词（债务人/本金余额/结欠利息/担保情况）②**跳过合计行要看前2列**（449 合计行首列空、"合计"在第2列）③担保类型从描述识别（抵押/保证/质押）④描述可能"质押+抵押"混合，**判断抵押物要看完整描述**（449 第4户前段是股权质押、后段才是房产抵押——只截前30字会误判不可尽调）⑤每户独立完整度评估
14. **京东页面信息源三层（2026-09-02 465 案例，抓取核心要求）**：京东债权页有**三层信息源，都要抓**——
   ① 公告表格（queryProductDescription 接口 HTML 的 `<table>`，部分公告无表格——465 的公告 raw_text 仅 135 字符）
   ② **页面 `<table>` 元素**（JS 渲染，如 465 的"债务人/债权合计/债权本金/利息/代垫/担保情况"表）——**此前只抓 div 属性区块漏掉 table**，已修复：`jd_page.fetch_jd_page_data` 抓所有 table，表头含 债务人/债权本金/债权合计 等为债权表，跳过出价/竞买记录表
   ③ **页面属性 div 区块**（"标的物详情/标的物属性"：债权本金/有无抵质押物/担保方式/抵质押物类型/抵质押物地址）
   抓取方法：接口(httpx, 快)→ 页面(Playwright)渲染抓 table+属性 div；批量同步用接口(快)，页面增强 enrich-jd(Playwright)补表格/属性/附件（单条或后台批量）

## 技能一：读懂原文 → 提取结构化字段（核心）

**场景**：数据源（京东/阿里/AMC 表）不规范，本金/利息/罚息/抵押物/债务人/担保方式等字段藏在公告原文文字/表格里。AI 必须从原文中提取并填入对应字段。

**总原则**：
1. **宁缺毋滥、绝不编造**：提取不到就不填（留空/—），绝不凭空造值（法规铁律精神）
2. **表格解析与文本正则双通道**：公告表格（headers+rows）按表头关键词定位列提取（最结构化），文本正则兜底；两者都要处理单位/格式差异
3. **权威值优先**：表格/属性区结构化字段优先；接口字段需认清语义（claimsMoney 可能是发放金额，2026-09-02 降级）；原文文本兜底
4. **单位跟随原文**：金额提取时保留原文单位（元/万元/亿），用 normalize_money 统一；表格单元格单位不统一时按表头推断（含"（元）"→元、含"万元"→万、无单位按量级猜）
5. **提取完整性自检**：表格里有的字段必须提取（利息/罚息/其他费用/合计/抵押物/保证人），不得因解析 bug 漏填——用户核心诉求是"从繁杂信息中获取我们需要的信息和数据"

## 字段提取规则（正则模式库）

| 字段 | 提取模式 | 示例 | 落地字段 |
|---|---|---|---|
| 本金 | `(债权本金\|主债权本金余额\|本金余额\|本金)\s*(合计)?\s*[为是]?\s*[:：]?\s*¥?\s*([\d,]+\.?\d*)\s*(亿元\|万元\|万\|元)`；京东优先 claimsMoney | "本金余额100.6126"→100.61万 | claim_total |
| 利息 | `(利息余额\|欠息\|利息)(（含[^）]*）)?\s*(金额)?\s*[为是]?\s*[:：]?\s*¥?\s*([\d,]+\.?\d*)\s*(亿元\|万元\|万\|元)` | "欠息1325.31万元"→1325.31万 | interest |
| 罚息 | `(剩余罚息\|罚息)(（含[^）]*）)?\s*(金额)?\s*[为是]?\s*[:：]?\s*¥?\s*([\d,]+\.?\d*)\s*(亿元\|万元\|万\|元)` | "剩余罚息427.5739"→427.57万 | penalty |
| 其他费用 | `(代垫费用\|垫付费用\|其他权利金额\|其他费用\|诉讼费\|律师费)\s*…`（累加；东方模板"其他权利金额"含律师费等）| "代垫费用278,227.32"→27.82万；"其他权利金额100.03万"→100.03万 | other_fees |

## 踩坑记录（重要）

1. **京东表格列不统一**：不同机构表格列序不同（[本金,利息,罚息,债务人] vs [债权余额,权属人,押品,保证人,本金,利息,代垫费用…]）→ **不能用固定列位置解析金额**，改用文本正则。
2. **表格解析曾产出错误值**：河源悦丰"利息 1001.72亿"（列错位+单位误判）→ 文本正则修复。
3. **单位陷阱**：公告表格单位可能"元"也可能"万元"；claimsMoney 是"元"。normalize_money 统一。
4. **"亲，请登录"不是验证页**：正常阿里详情页导航也含，验证页判定词用"拖动滑块/nocaptcha"。
5. **债务人提取杂质**："拟将/公开竞价/公开处置/等N户"要清理；多债务人（65人）→ debtor_count + 名单，"见详情"。
6. **阿里 sf-item 详情页需登录**：原文/本金暂无法自动获取，保留源链接。
7. **详情页链接**：京东用 `paimai.jd.com/{auctionId}`（pmsearch?auctionId 是列表页）。
8. **⚠️ 表格解析不得要求"首列为数字"（2026-09-01 用户反馈）**：此前 `if row[0].isdigit()` 导致首列是"项目/债务人名"的金额表**整表被跳过**，利息/费用/抵押物从未提取（参考图案例：湖南张家界大成山水"利息/代垫费用/抵押物"全没填，实际公告表格里全有）。**修复**：按表头关键词定位列（`_col_index`），不依赖首列类型。
9. **⚠️ 合计行因合并单元格会列错位（2026-09-01 发现）**：合计行（"合计"跨列合并）后续值整体左移，取合计行值会张冠李戴（如把"其他债权 39.64"当"利息"）。**修复**：弃用合计行，改为**逐列对数值行求和**（跳过含"合计"的行），求和不受错位影响且与合计一致。
10. **⚠️ 表格单元格单位不统一（2026-09-01 发现）**：同一批表格有的列是"元"（44,699,945.91）、有的列是"万元"（355.55）。**修复**：按表头推断单位（含"（元）"→元、含"万元"→万），无单位按值量级猜测（≥1万视为元，否则视为万）。
11. **⚠️ 东方资产模板是【】格式**：`未偿利息人民币【10,924.22】万元`——正则须支持 `[【\[]…[】\]]` 包裹；"其他权利金额"（含律师费等）归入 other_fees。
12. **⚠️ 抵押物可能藏在"担保情况/担保详情/担保措施"列**：表头不叫"抵押物"时也要匹配这些词（列内容常同时含抵押+保证描述）。
13. **⚠️ 竖排键值表三种形态（2026-09-01 扩展）**：京东"债权标的情况表"是竖排键值表，三种形态都要兼容：
    - A. `['', '键', '值', '键2', '值2']`（行首空，安徽新安银行）→ 从 index1 开始
    - B. `['键', '值', '键2', '值2', '']`（无空单元格，威海银行）→ 从 index0 开始
    - C. 长文本值（威海"债权本息"列含"本金余额X元，利息、罚息等合计Y元，诉讼费用Z元"）→ 正则从文本提取
    - 落库：`_parse_kv_table` 自动探测起始位；sync 映射"本金/利息、罚息/垫付费用/资产类型/抵质押物/诉讼情况/地区"
14. **⚠️ 表头子行与合计行（2026-09-01 修复）**：跨列表格常有子表头行（如 367 河源悦丰"本金余额/利息/小计"作为第二行）和合计行（"合 计"含空格）；跳过判断须**去空格**后匹配"合计/总计/小计"，子表头行按首列"本金余额"等识别。
15. **⚠️ 阿里资产标题提取**：本金从标题提取（"5049222.62元"/"4851万元"/"6.3亿"/"1亿余元"）；抵押物线索词（"房抵"→住宅房产、"有土地线索/查封土地"→土地厂房）；标题无金额/无抵押的（信用类/应收类）**留空不造**——绝不拿起拍价冒充本金。
16. **阿里 H5 网关直连（2026-09-02，破解淘宝列表接口签名）**：httpx 直连 `h5api.m.taobao.com` 拿阿里资产债权列表（无需浏览器/登录，替代 Playwright）：
    - **签名**：`sign=MD5(token & t_ms & appKey & data)`；token=普通 GET 任意 mtop 端点（如 `mtop.taobao.datafront.invoke.auctionwalle/1.0/?sign=0000...`）后服务端下发 `_m_h5_tk` cookie，取 `split("_")[0]`（前32字符）；appKey=12574478
    - **调用**：POST `h5/mtop.taobao.datafront.invoke.auctionwalle/1.0/`，query 带 jsv=2.6.1/appKey/t/sign/bxPageId=1910955/api/v/type=originaljson/dataType=json/requiredParams=dfApiName,dfUniqueId，body `data={dfApp:"auctionwalle",dfApiName:"auctionwalle.datou.getPageModulesData",dfVariables:"<json字符串>",dfUniqueId:"1910955.2004318340:items,2068791300:recommend",dfVariablesRecover:"{}"}`
    - **dfVariables**：`{"pageId":1910955,"moduleIds":"2004318340:items,2068791300:recommend","context":{"_b_2004318340:items":"{\"fcatV4Ids\":[\"206067301\"],\"page\":\"1\",\"userInfo\":{},\"appendMap\":{\"sid\":\"随机数_毫秒\"}}","userInfo":"{}","device":"pc","sceneCode":"20210823QCG72BUD","appendMap":"{\"isAutoSelect\":true}"}}`
    - **响应**：`data.data.GQL_getPageModulesData["2004318340"].items.schemeList`（40条/页）；条目字段：auctionTitle/auctionBenefits(本金:XX|利息:XX|抵押物:XX,覆盖率~87%)/status(ing|before|end)+statusOrder(0|1|2)/price+priceUnit(万|亿)/bidCnt/subscribeCnt/circ/startTime/endTime/shopName/auctionLink/itemId
    - **关键坑**：①`auctionwalle.page.getScenes`(H5版) 返回 contentList **无 auctionBenefits**，必须用 `auctionwalle.datou.getPageModulesData`+`:items` 后缀才带；②首屏 getPageModulesData 的 items 为空，列表在**第二次(滚动触发)请求**，参数带 `_b_2004318340:items`；③sid 需随机数_毫秒时间戳
    - **token 失效自愈**：ret 含 TOKEN_EMPTY/TOKEN_EXPIRED/ILLEGAL_ACCESS::Sign Error!/ILLEGAL_REQUEST → 清 cookie 重 bootstrap 重试一次
    - **过滤**：fcatV4Ids=206067301(债权)、statusOrders=["0","1","2"]、zcBizTypes=["8"](破产)、circs/tagIds/provs/citys/locationCodes

## 技能二：原文表格 → 自建表格（用户确认方案）

**场景**：公告原文表格不加修饰地摊成文本用户看不懂。方案：**自建表格**（从原文表格解析成结构化数据，AntD Table 渲染），文字描述保留上方，源链接兜底。

**实现**（jd_credit.fetch_jd_detail_money）：
- 解析 HTML `<table>` → `{headers, rows}` → detail.announce_table
- 前端：`招商信息原文` 卡片内渲染 AntD Table（列宽按字段类型：金额列 120、文本列 160；scroll x max-content）
- 金额（本金/利息/罚息）：优先按表头关键词定位列（"本金/利息/罚息"），避免固定列序

**注意**：
- 基本信息"抵押物"栏**只显示类型**（住宅房产等），超长描述/担保措施放原文表格与文字（避免撑错位）
- 多户债权：正文"整包合计"金额 vs 表格"单户"金额——文本正则优先取正文整包值，表格只作兜底
- 利息正则含"利息及孳息"（正文"利息及孳息578.34万元"能匹配，避免误取表格单户值）

## 技能三：金额标准化

`normalize_money`：'5049222.62元'→'504.92万'、'139109.0万'→'13.91亿'、'1亿余元'→'约1亿'、'2.47312万'→'2.47万'。规则：≥1亿用亿、≥1万用万、否则元；去尾零；原文含"约/余/近"标"约"。

## 技能三：标题精简

`shorten_title`：去【】营销前缀（"【贯通拍卖314】"），保留"债务人+债权性质"核心，两行内（≤34字）。

## 技能四：可尽调判定（2026-09-02 用户确认细化）

**三要素缺一不可**：债务人名称 + 债权金额 + **抵押物合格** = 可尽调；缺任一 → 列表禁勾选、尽调按钮灰、创建任务后端拒绝。

**抵押物合格 = 房产/不动产类 + 描述具体**（同时满足）：
- **房产类**：住宅 / 商业 / 工业 / 土地 / 厂房 / 写字楼 / 商铺 / 公寓 / 别墅 / 仓储 / 车位 等不动产；**排除** 机器设备 / 股权 / 应收账款 / 车辆 / 存货（我们只对房产估价）
- **描述具体**（至少一项）：
  - 位置细节：路、街、大道、巷、弄、小区、苑、花园、幢、栋、层、室、镇、村、**县、乡**、**高新区/保税区/开发区/金融区** 等专有区域
  - 面积：㎡ / 平方米 / 平米
  - 证号：权证 / 房产证 / 不动产权证 / 登记证明
  - 门牌号模式：`\d+号/幢/栋/室/层/单元`
- **不算合格**：纯类型词（"住宅房产"/"房产"/"商业用房"）、只有大范围（"青岛市黄岛区"，普通"XX区/XX市"不算）、无任何具体信息

**实现**：后端 `extractor.is_valid_collateral`（evaluate_completeness + tasks 创建校验共用）+ 前端 `utils/claimEligibility.js`（hasValidCollateral/canDueDiligence，详情页/列表页按钮共用），前后端规则一致，44 pytest 全绿。

## 技能五：唯一住房判断（用户规则 2026-08-31，逻辑类）

**规则**：
1. **多套住宅**（如 60 套）明显不是唯一住房 → **不触发**唯一住房提示
2. **单套住宅**（可能唯一住房）→ **条件式提醒**："若为自然人唯一住房，执行难度会加大，需保障基本居住（安置或扣除5~8年租金）；请核实是否唯一住房"——**未确认不能下定论**
3. **明确写"唯一住房"**（原文/录入）→ 才可定论提醒

**实现**：reminder_engine.py `_count_collaterals`（套数统计：第X号证号 > 证号 > N套(数字/中文) > 名下/位于）；A9（已确认）+ A9b（可能，条件式）；recovery_planner 住宅风险文案、due_diligence LLM 规则注入同规则。
