## 1. 深挖功能（**未开始**；2026-09-04 多次讨论，开工前必读 + 提醒管理员）

**功能定位（管理员确认）**：用户一般"先查财产线索 → 不满意才深挖"；深挖时会命中财产线索已"钻"的缓存，所以财产线索+深挖对同一主体≈一次查询成本（理论）。

**成本机制（重点，管理员 2026-09-04 指出我方估算错误）**：
- 企查查"同主体月封顶 100 积分"是**按主体**的，不是按单/按次
- 深挖拉出的**关联企业 = 独立主体**：每个关联方各自计费、各自有 100 分封顶；一次深挖若对多家关联方钻取，可能 主企业 100 + 每家关联方几十~100 分 → **数百积分/几十元**，且关联方可能不止一家
- 结论：**深挖成本无法用"100 分封顶"兜底**，必须在关联方钻取环节做节流

**开工前需管理员拍板的决策**（当时未定，深挖开工时确认）：
- A. 深挖的关联企业钻取**默认不钻**：主企业扫+钻后，列出关联企业清单，用户勾选要对哪几家钻（弹窗列每家预估分）——最省、最可控（倾向此方案）
- B. 自动钻但限制最多 N 家（成本可控但可能钻到无价值关联方）
- C. 其它口径
- 附加可选：只钻"有价值"关联方（控制权高/实控人本人/疑似壳）；单次深挖关联方钻取上限；钻取前核对弹窗列预算

**进度约定**：深挖功能开工时，**先提醒管理员**：①读本条讨论 ②确认 A/B/C 决策 ③确认预算口径。
