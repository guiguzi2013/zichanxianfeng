# 资产先锋 · 约定速查（一页版）

> 上下文压缩/新会话后**第一步先读本页**（10 秒）。详细版见 `备份/产品决策与约定.docx`。
> 最后更新：2026-09-05（新增第37条：施工汇报只进对话框，不进产品）

## 平台边界（最高原则）

**不做**：债权估值、买入决策、利润公式展示。
**只做**：为不良资产从业者/投资者提高工作效益——所有前台页面与后台功能皆为此设立。

## 约定速查（29 条）

1. **主题**：不良资产，债权是主线，一切功能围绕它
2. **用户**：不良资产从业者/AMC/个人投资者
3. **使命**：用户目的=追回欠款，告诉用户下一步做什么
4. **UI**：改 UI 必兼顾 H5 手机版
5. **自然人**：不用公司模板，没的写就空着
6. **核对弹窗**：查询前列出全部主体+预估积分，确认后再查
7. **上传文案**：用"判决书/裁定书/情况说明等材料"
8. **积分**：大额消耗先确认预算
9. **积分省用**：缓存优先、自然人不查、失败不缓存
10. **报告**：对象=律师，围绕收回欠款，区分已确认事实与需司法调取
11. **知识库**：内部工具，不展示前台
12. **记录**：用户说"你记住"→ 同步写入约定文档
13. **进度**：整体进度优先，不死磕小功能
14. **不确定先确认**：复述理解+列疑点，避免返工
15. **动手前先确认（核心）**：收到需求先列 ①理解 ②怎么改 ③疑点 → 等确认再动手（纯 bug 修复/用户明确"直接做"除外）
16. **权限弹窗**：合并操作，减少确认次数
17. **知识提醒**：知识类/逻辑类讨论主动问用户是否记入知识库
18. **建议先评估**：用户提的修改建议，先判断合理性，不合理要说明理由+替代方案；仅当用户明确"必须按我说的做"才无条件执行
19. **记忆总纲**：`docs/项目记忆总纲.md` 为单一恢复入口，本页为其速查
20. **先扫后钻（铁律，2026-09-04 增补只扫不钻）**：调用任何外部数据接口（企查查及未来其他 API）一律先低成本扫描、命中才钻明细，禁止无差别全量调用；配套共享缓存/失败不缓存/负缓存/预算确认。**例外（用户拍板）**：债权尽调、债务人画像两类工作流=**只扫不钻**（risk_scan 命中清单进报告，不主动调明细工具；案号/示例仅复用缓存已有明细=零积分）；财产线索、深挖=先扫后钻（钻取）
21. **尽调=债权初筛**：尽调聚焦债权本身（本金/利息/抵押物/覆盖/司法状态），帮用户初筛哪笔债权值得跟进；司法风险=只扫命中清单（2026-09-04 用户拍板，不钻明细）；债务人深层财产线索由财产线索功能承担。**2026-09-04 更新**：尽调主动查股东+变更（进共享缓存，供画像/线索复用，一次查透），报告有则显示股东区块
22. **长期共享缓存（1年）**：企查查缓存 TTL=1年（基本信息变化小）；利息走"旧报告+新算"（实时计到报告当日）；报告标"数据截至X年"、生成日期写当日；共享=债务人+债权双维度；补充续期1年；**强制刷新仅单条+仅管理员**（无全量刷新，防误点）；用户资料私有只共享查询结果；债权补充材料不调接口，财产线索补充独立主体才查
23. **财产线索报告落库**：综合分析/深挖报告存 clue_reports 表；后台「报告数」=尽调+财产线索总数；点开 Tabs 三列表（尽调/财产线索/深挖占位）；员工可看+查全文（客服用），清缓存仅管理员；员工查看报告报错已修复（versions 放行 admin/editor）
24. **在线统计**：login_sessions 会话表记录每次登录/登出；用户列表显示 最后上线时间 + 今日在线时间(自然日累计,进行中标注)；管理员点「登录记录」看该用户全部登录时段(分页)
25. **字段提取完整性（铁律）**：表格里有的字段必须提取（利息/罚息/其他费用/合计/抵押物/保证人），不得因解析bug漏填；表格解析按表头定位列（勿要求首列数字）、勿用错位合计行、单位按表头推断；东方【】模板正则支持；详见必备技能库踩坑8-12
26. **页面列宽统一（铁律，反复犯错点）**：所有页面容器 maxWidth 一律 1200；改布局前先 grep maxWidth 对照其他页面；列表列宽规范 首列340/数值列120/短列100
27. **京东页面增强+附件**：公告附件(资产清单/评估报告/判决书等 word/excel/pdf)Playwright 渲染页面提取→下载到服务器关联债权；详情页+尽调报告页"重要文件"可下载；评估报告2年内直接采用估值、超2年走成本法；格式文件(承诺书/保密函/模板)跳过
28. **自研QCC工作流（不照抄官方SKILL全量，只调需要接口；2026-09-04 只扫不钻）**：①债权尽调=工商(3)+股东(20)+变更(5)+risk_scan(5)（只扫：命中清单/条数进报告，不钻明细；案号示例仅复用缓存）≈33分/主体 ②财产线索=工商+股东+对外投资+分支+司法/权益类 先扫再钻≈4-8元 ③深挖=关联企业(related_risk_scan先扫)+历史投资+隐藏实控人+实缴≈6-12元（关联方独立计费） ④债务人画像=基础工商工具组(10项)+risk_scan(5)（只扫）≈62分/主体；多工作流共享工具缓存不重复调用；月封顶100积分/主体=10元
29. **未登录下载弹登录框**：点下载未登录→弹"登录后继续"Modal(LoginModal组件)，登录成功留在原页自动继续下载；401拦截器不弹原始英文错误
30. **阿里 H5 网关直连（2026-09-02）**：淘宝/阿里资产列表用 httpx 直连 h5api.m.taobao.com（MD5签名+_m_h5_tk cookie，替代 Playwright，1.6s vs 30-60s）；dfApiName=auctionwalle.datou.getPageModulesData+`:items`后缀才返回带 auctionBenefits(本金/利息/抵押物)的 schemeList；fcatV4Ids=206067301 债权类目、statusOrders=0/1/2 进行中/即将开始/已结束、zcBizTypes=8 破产；**详情页仍强制登录**（利息明细/债务人/保证人/担保方式无法自动获取，保持"未披露"+源链接）
31. **动手前先确认（2026-09-02 用户强调，铁律，违反实例：用户说"测试"我未确认就在后台跑真实QCC查询花50分）**：重要问题动手前必须得到用户确认。**动手前三问自检**：①会花钱/耗积分或调外部付费接口吗？②会改/删数据库吗（写操作/清缓存/删记录/落库）？③中途被打断能否完全撤销？任一"是/不确定"→先停发方案等确认。**红区操作清单**（先说明做什么+花什么+影响什么，等确认才能执行）：外部API真实调用(耗积分/费用)、数据库写/删/改、批量操作、方案性改动(改版/规则/新功能)、用户说"测试/试试/看下"但没说具体怎么做→默认先问。**能省则省**：涉及花钱的默认先给零成本预演（列将调工具+预估积分，或先用缓存走通）。**违背即停**：未确认就动手被指出后立即停止并说明影响
32. **自动预填原则（2026-09-02 网站原则，长期生效）**：能提取对应的字段都要预填，给用户方便友好的体验。**不需特意全面排查**，但每次改到相关代码（表单弹窗/字段展示/报告渲染/录入入口）时，符合"有对应提取字段"就顺手按自动预填规则改。配套：LLM 提取已扩 房产证/面积/年份/结构/证号/权利人/用途/抵押登记 等字段（extractor），PreviewPage/TaskClaimsPage 编辑弹窗已自动预填，报告 web+PDF 展示明细；不编造（原文无则留空）
33. **完成工作先自查（2026-09-02 用户强调，铁律）**：声称"完成"前必须**自查**——改动是否覆盖全部受影响范围（单条修复≠全量修复，如只修了453没批量修存量京东债权）、是否引入回归（放宽解析条件可能误抓）、是否补了测试、数据是否落库生效。**绝不能让用户先查出来再返工**（浪费时间且显失专业）；自查发现遗漏自己补完，实在搞不定才给建议
34. **检查清单驱动工作法（2026-09-02 用户强调，铁律）**：对待问题**像飞机起飞前的检查清单——按单核对，不依赖记忆**。①按单核对：修改/抓取/回填前对照既有清单逐项核对 ②同类问题最优解清单：每次修改总结经验记录（问题→根因→最优解），**有更优方法必须更新** ③遗漏台账：每次遗漏立即记入检查表，记多了不再遗漏。适用于所有问题（不只抓取）：每类问题建清单、每次修改总结、每次遗漏记台账
35. **抓取内容排版再发布（2026-09-03 用户强调，铁律，用户原话"以后所有抓取来的内容都要经过排版再发布"）**：禁止文字堆砌——①正文剔除已自建表格的文字（表格文字不进正文：Playwright 用 display:none 隐藏表格后取 innerText 保段落结构，httpx 源先删 <table> 标签）②排版函数 text_extract.layout_notice_body（去导航/噪声/重复头→段落列表，字段行独立段）③正文关键指标回填（extract_notice_metrics：户数/总金额/本金/利息/编号/截止日→指标卡与 Descriptions）④前端按段落逐段渲染、空摘要卡隐藏。适用所有抓取来源（AMC/报纸/京东/阿里等）
36. **使用者 vs 管理员信息边界（2026-09-04 用户明确，铁律）**：网站的使用者=不良资产从业者（一切界面为其服务）；用户（老板）=管理员；AI=执行者。**术语约定：以后老板说"用户/客户"指的都是网站使用者，不是老板本人；老板本人=管理员**。面向使用者的界面**不得出现**：数据供应商名（企查查等）、查询成本/积分/费用、缓存等实现机制；这些内部信息只出现在 AI↔管理员的汇报/后台。例外：正式报告的数据来源标注保留（专业文档惯例）
37. **施工汇报只进对话框，不进产品（2026-09-05 用户强调，铁律，用户原话："网站是给其他人看的，不是给我看的；你想跟我表达什么在这个对话框里表达就可以，没必要放到网站上；不要在项目里告诉我你做了什么、没做了什么、什么原因没做"）**：网站/App 界面是**给使用者的成品**，不是给老板的施工日志。所有"我做了什么 / 没做什么 / 什么原因没做 / 下一步计划"一律只在本对话（或后台管理界面）与老板沟通，**禁止做成界面文案、提示条、Alert、占位说明展示给使用者**——尤其禁止向使用者解释"数据为何缺失/为何要登录/抓取限制"这类替施工方开脱的说明。写任何界面文案前自问：这句话是给使用者用的，还是向老板汇报的？后者→不放界面，放对话框。**违反实例（2026-09-05）**：详情页"阿里资产详情需登录查看…"提示被用户两次圈出——使用者登录后看到的仍是同样字段，该提示只对老板有解释价值，对使用者是噪音且暴露平台数据不全。同类已清理：HomePage"暂无数据请在管理后台录入"、工具页"新增N次调用/缓存命中M次"统计、"企查查Demo"整页路由等

## 核心业务规则（一句话）

- **计息**：计到报告当日（截止日+LPR续算 / 判决书精确 / 无信息用录入值+注明）
- **覆盖**：覆盖率=本息÷抵押物估值；≥100%覆盖（好事），<100%未覆盖（处置后可能倒找债务人钱，必须提示）
- **评级**：只给星 ★~★★★★★（>150%五星 / 100-150%四星 / 70-100%三星 / 40-70%二星 / <40%一星），不给文字建议
- **情景分析**：只列 本金+利息 与 抵押物估值区间+本息合计，禁 7折/8折 表
- **估值**：只做工业土地厂房(成本法)与商业房产(市场价取最低)，不做住宅估价
- **处置方案**：多路径并列（上拍/以物抵债/其他），绝不推荐单一
- **法律铁律**：法规绝对禁止编造，只引知识库真实法规（含文号）；没有就不写
- **代偿**：担保公司替债务人还款后成为债权人（追偿权），可转让该债权；金额=代偿+担保费+滞纳金+垫付
- **融资租赁债权（2026-09-04 用户拍板）**：直租/售后回租两类都可能产生债权；"抵押物"是设备（租赁物）非房产。识别=输入含"融资租赁/售后回租/回租/融资租赁合同"字样；有房产抵押→按正常处理（照常估值）；无房产+识别出融资租赁→视同有抵押物可尽调，**不做设备估价、不写覆盖率**，抵押物区块列设备清单或写"设备租赁"；无房产且识别不出→抵押物缺失不予尽调。知识已入知识库
- **尽调输入（2026-09-04 用户确认）**：输入页=粘贴文本 + 上传文件（Excel 批量清单 / Word/PDF/图片 材料识别，材料识别提取 债务人/债权人/本金/利息/利息计算方式/是否胜诉 等回填报告，不存原件）；已删"粘贴链接"（淘宝抓不到，无意义入口）
- **信息源**：精选债权=京东债权+阿里金融资产债权（只留进行中/即将开始，滤破产）；捡漏=破产专区小额（≤100万）；债权公告暂不采集
