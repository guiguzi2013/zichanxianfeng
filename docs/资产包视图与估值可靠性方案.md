# 资产包视图 / 估值可靠性分级 / 中国 NPL 披露标准 —— 借鉴国外平台落地方案

> 2026-09-09 起草(依据 NPL Markets、Debitos、EBA ITS 2023/2083、Drooms、Neotas、ATTOM、Xclaim、Auction.com、IPAF 东南亚蓝图 等公开资料)
> 原则:借鉴"功能形态"(数据标准化/组合统计/置信度披露),不照搬"机构对机构撮合/现金流折现定价"模式;不越平台边界(不做买入建议/交易撮合)。

## 一、国外平台功能拆解(他们到底做了什么)

### 1. 组合级分析(NPL Markets)
- 把整包 loan tape(逐笔贷款数据表)载入平台 → 得到**组合仪表板**:总本息、笔数、地区/担保/逾期账龄分布;
- 逐笔跑回收模型再**加总到组合**:基准/上行/下行三情景回收额与回收率、折现估值;
- 同一套数据同时服务卖方(组包卖)与买方(复核出价),强调"独立第三方定价"。
- 对我们启发:他们按"逐笔→加总"出组合视图,数据粒度在贷款级——与我们"每笔债权一份报告"天然同构。

### 2. 数据标准化(Debitos / EBA)
- 欧盟 2023-09-26 正式立法(EU Implementing Regulation 2023/2083):银行卖 NPL 必须按 EBA NPL Transaction Templates 提供标准化数据,否则交易数据不合规;
- 模板结构(数十页 Instructions):①交易与组合概览 ②债务人信息 ③贷款级数据(本金/利率/逾期天数/法律状态…) ④抵押物数据(地址/类型/估值基准日/顺位/他项) ⑤司法催收数据;每字段带 **ND1/ND2 质量标记**("未采集"/"已采集未入系统")——卖方要如实标注缺口,买方据此判断数据可信度;
- Debitos 围绕它做商业:**Data Converter(把银行内部五花八门的导出转成 EBA 标准)+ 组合分析 + 订阅制服务**——证明"标准化不是免费的,是独立生意"。
- 对我们启发:我们平台的"材料解析成结构化字段"本质上就是中国版 Data Converter,只是散在单笔报告里,未沉淀为"标准字段清单"。

### 3. 估值透明与置信度(ATTOM/CoreLogic)
- AVM 输出"估值 + 区间 + **置信度评分**",数据充分度直接影响置信度,甚至叠加卫星影像;让使用者知道"这个数有多可信",而不是给一个孤零零的数字。

### 4. 数据室与 AI 文件审阅(Drooms)、披露卡片(Xclaim/Auction.com)
- Drooms:整个资产包的贷款文件进数据室,AI 问答并定位原文段落(如"该户抵押物有无他项权利");
- Xclaim/Auction.com:要交易先备齐"披露数据包"(权属/欠税/评估/文件),齐不齐一目了然。

## 二、中国国情适配判断

| 国外做法 | 国情差异 | 结论 |
|---|---|---|
| 现金流折现三情景定价(银行模型) | 国内民营 AMC 买包看:本金折扣、抵押物可变现价值、司法确定性(首封/轮候/顺位)、处置周期 | **不做折现定价**,用我们的"抵偿度 + 司法状态 + 处置路径"作分档语言 |
| EBA 全套合规模板(监管强制) | 中国无此监管,卖方数据仍是公告+材料包(word/Excel/判决书),格式五花八门 | **取其字段清单精神,做中国版"标准披露清单"**(这正是二期),平台做先行者 |
| 机构对机构数据室/撮合 | 我们是公开信息+从业者自助工具 | 不引入撮合;把"数据包齐不齐"用披露完整度表达 |
| ND1/ND2 数据缺口如实标注 | 与我们"需人工核实/待补充"异曲同工 | 升级为**披露完整度(每笔 X%)**,前端可见 |
| 置信度评分 | 直接可用 | 做"估值依据分级",并入报告与包统计 |

## 三、功能一:资产包视图(组合分析)——一期 P0

**触发与位置**:一次尽调任务勾选 ≥2 笔债权(现有"勾选多笔一次尽调"已支持)→ 任务自动附带"资产包分析"。入口:任务详情页/我的报告页,多笔任务显示"资产包分析"入口(卡片或 Tab)。

**页面结构(资产包分析页)**:
1. 顶部数字卡:包内笔数 / 本金合计 / 本息合计 / 抵押物参考估值合计 / **加权抵偿度** / **缺口合计**(抵偿度<100% 各笔缺口之和)/ 覆盖足额笔数;
2. 分布条块(四张小型分布卡,数据不足自动隐藏):
   - 地区分布(按省/市);
   - 担保类型分布(抵押/保证/混合/信用);
   - **抵偿度分档**(≥150% / 100~150% / 70~100% / 40~70% / <40% / 无法估值);
   - 司法状态分布(未诉讼 / 审理中 / 已判决 / 执行中 / 终本 / 破产 / 待核实);
3. 明细表:每笔一行(债务人/本金/利息合计/抵押物简述/抵偿度+星级/司法状态/缺口金额/操作→进入单笔报告);默认按"星级降序+缺口升序"排序,顶栏小字注明排序维度即可(不替用户决策);
4. (二期)估值可靠性占比条:高/中/低各占几笔,让"估值合计"可信度可视化。

**数据来源**:全部来自各单笔报告最新版 content 的 conclusion_bar / summary.rating / collateral.coverage_vs_interest / claim_basic / judicial 字段——**无新外部查询、零积分、无 LLM 成本**;聚合接口:按 task_id 读该任务全部报告最新版实时计算。

**改动点**:
- 后端:新增 `GET /api/tasks/{id}/portfolio`(聚合统计,纯计算);
- 前端:新页面 PortfolioPage.jsx(统计卡+分布+明细表,AntD Table),任务/报告页加入口;
- PDF(二期再做):包级汇总 PDF(一页)。

## 四、功能二:估值依据分级——一期 P1

**五级定义(对外措辞用"估值依据"不用"可靠性"字样外的自造词)**:
- **评估报告**:2 年内正式评估报告直接采用(现有逻辑已支持);
- **证载齐全**:有产权证号+类型+面积+建成年份等结构化字段(市场法/成本法粗估但输入扎实);
- **文本粗估**:仅描述文本提取(面积/类型来自文本,无证号);
- **信息不足**:缺类型或缺面积 → 不展示估值数,沿用"建议正式评估"。

**落地**:
- 估价模块输出加 `basis: {level, label}`(如 level=report/appraisal_doc/text/insufficient;label 一句话原因);
- 抵押物卡与 PDF:估值旁 Tag+一行依据说明;顶部结论条"抵押物估值(粗估)"不变;
- 资产包视图的估值合计旁标注"其中 N 笔为评估报告依据、M 笔为文本粗估",避免把低质量估值当实数加总;
- 旧报告不回溯,重新尽调后生效(与全站惯例一致)。

## 五、二期:中国 NPL 债权披露标准(平台先行者路线)

**目标**:网站成为国内第一个把"一笔债权到底应披露哪些字段"固化成公开清单的平台,反哺从业者与行业。

**第一步(二期初,文档先行)**:发布《资产先锋债权披露字段清单 v1》,分组草案:
1. 债务人信息:名称/类型/统一社会信用代码/登记状态/注册资本与实缴/涉诉执行概况;
2. 债权要素:本金/利息口径与截止日/计息方式/债权形成(借款/垫款/代偿)/转让背景/原债权人;
3. 担保:担保类型/保证人信息/保证方式/保证期间;
4. 抵押物:类型/完整地址/权证号/面积(土地/建筑)/用途/建成年份/估值(报告或粗估)/**他项权利与顺位**/**首封轮候与查封法院**;
5. 司法程序:诉讼阶段/案号/判决情况/执行法院/执行进度/终本信息;
6. 资料附件:借款合同/保证合同/抵押登记证明/判决书/裁定书/催收记录。
每字段标注:来源(公告/上传材料/外部数据/人工)、缺失影响、"待补充"入口——与现有"待补充信息"机制打通。

**第二步**:详情页与录入表单按清单分组;单笔报告"披露完整度 X/XX 项(X%)"进度条(ND 精神的本土化,但面向使用者只说"完整度")。

**第三步(对外)**:清单文档化发布(网站"行业标准"页/公开文档),向从业者、合作机构、AMC 输出;未来可走团体标准/论坛研讨路径——网站因此具备"定义行业数据语言"的先发身位。

## 六、排期建议
- 一期 A(资产包视图):约 2-3 天(纯前后端聚合,零外部成本);
- 一期 B(估值依据分级):约 1-2 天;
- 二期(披露清单 v1 草案 + 完整度):文档先行 1 天出 v1,功能 3-5 天;
- 全程遵守:不引入折现定价/买入建议;新报告才生效;界面不出现"系统/内部"词。
